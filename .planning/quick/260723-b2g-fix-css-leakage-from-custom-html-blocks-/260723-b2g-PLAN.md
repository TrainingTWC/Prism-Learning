<objective>
Fix CSS leakage from custom-html blocks. Author-pasted HTML containing `<style>`/`<link>` tags currently becomes a global stylesheet (DOMPurify does not strip style/link), landing after the app's CSS in cascade order and winning on equal specificity — e.g. a pasted `body { font-family: ... }` or `:root { --prism-font-heading: ... }` changes the lesson title font elsewhere on the page.

Fix (already decided — do NOT reconsider): wrap each custom-html block's rendered output in an open Shadow DOM root. Shadow DOM scopes the pasted CSS so it can neither leak OUT to the rest of the page nor be affected by the app's CSS bleeding IN — while still applying to the author's own widget markup inside the block. DOMPurify sanitization is unchanged (React path); SCORM export raw-HTML behavior is unchanged aside from the mount mechanism.

Purpose: Authors intentionally paste styled interactive widgets; they expect their CSS to apply to their widget but not corrupt the rest of the lesson.
Output: Both render paths (live React renderer + SCORM/preview export) mount custom-html content inside a shadow root.
</objective>
