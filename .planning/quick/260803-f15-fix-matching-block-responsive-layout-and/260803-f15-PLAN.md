# Quick Task 260803-f15: Matching block layout + touch support

## Problem

Learner preview (phone viewport, 390px) renders the `matching` block broken:

- `.prism-mt-cols` uses `grid-template-columns:1fr 1fr` — grid items default to
  `min-width:auto`, so columns cannot shrink below their content and the block
  overflows its card.
- `.prism-mt-term strong{flex-shrink:0}` — the term label can never shrink, so it
  pushes the "Drop here" slot outside the term row.
- Definitions have no `overflow-wrap`, so long words render one-per-line in the
  squeezed column.
- Two side-by-side columns are unusable at phone width regardless of overflow.
- HTML5 drag-and-drop does not fire on touch devices, so the block cannot be
  completed at all on a phone — the very viewport being previewed.

The preview iframe is generated by `buildPreviewHtml` in
`apps/web/src/lib/scormExport.ts`, so the export CSS/HTML/JS is the source of the
screenshot. `packages/renderer/src/MatchingBlockRenderer.tsx` has the identical
bugs and must be kept in parity.

## Tasks

### Task 1 — Fix export CSS + markup + interaction JS

**Files:** `apps/web/src/lib/scormExport.ts`

**Action:**
- `.prism-mt-cols` → `repeat(auto-fit,minmax(240px,1fr))` so columns stack when the
  container is narrower than ~500px (container-driven, works in preview and LMS).
- Add `min-width:0` to the two column wrappers.
- `.prism-mt-term` → `flex-wrap:wrap`; `strong` → `flex:0 1 auto;min-width:0` with
  `overflow-wrap:break-word`; slot → `flex:1 1 140px;min-width:0` so the slot drops
  to its own line instead of overflowing.
- Add `overflow-wrap:break-word` to `.prism-mt-def` and `.prism-mt-slot`.
- Replace `.prism-mt-check{float:right}` with `display:block;margin-left:auto`.
- Add `Terms` / `Definitions` column headings (parity with the React renderer,
  needed for comprehension once stacked).
- Rewrite the block's inline JS around `place(term, def)` / `clear(term)` so it
  supports: drag-drop (unchanged), tap-to-select a definition then tap a term to
  place it, tap a filled term to send the definition back to the bank, and
  replacing an already-filled slot without losing the previous definition.
- Placeholder text `Drop here` → `Tap or drop` so the touch affordance is discoverable.

**Verify:** `pnpm -C apps/web exec tsc -b --noEmit` (or repo typecheck) passes.

**Done:** Matching block stacks to one column and stays inside its card at 390px;
a definition can be placed by tapping.

### Task 2 — Mirror the fix in the React renderer

**Files:** `packages/renderer/src/MatchingBlockRenderer.tsx`

**Action:** Same layout rules via inline styles (`minmax(0,1fr)` auto-fit grid,
wrapping term row, shrinkable term label, break-word), plus tap-to-select/place
state alongside the existing drag handlers.

**Verify:** Package typecheck passes.

**Done:** Renderer demo page matches export behaviour.

## Must haves

- Matching block does not overflow its container at 390px width.
- Term text wraps instead of pushing the slot out of the card.
- Block is completable without a mouse (tap-to-place).
- Drag-and-drop still works on desktop.
- SCORM export CSS/JS remains self-contained (no new deps).
