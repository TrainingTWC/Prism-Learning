# Quick Task 260803-f15: Matching block layout + touch support — Summary

## What was wrong

Screenshot showed the "match the following" (matching) block broken in the
learner preview at phone width (390px):

- `.prism-mt-cols{grid-template-columns:1fr 1fr}` — grid tracks default to
  `min-width:auto`, so the two columns couldn't shrink below their content and
  the block overflowed its card.
- `.prism-mt-term strong{flex-shrink:0}` — the term label could never shrink,
  pushing the "Drop here" slot out of the row.
- No `overflow-wrap` anywhere, so long definitions rendered one word per line
  in the squeezed column.
- HTML5 drag-and-drop (`draggable`, `dragstart`/`drop`) is desktop-only —
  `dragstart` never fires from a touch tap, so the block was uncompletable on
  a phone at all, independent of the layout bug.

## What changed

**`apps/web/src/lib/scormExport.ts`** (the actual render path — this is what
`buildPreviewHtml` feeds into the preview iframe and the exported SCORM zip):
- `.prism-mt-cols` → `grid-template-columns:repeat(auto-fit,minmax(240px,1fr))`
  so it collapses to one column once the container is narrower than ~500px,
  with `min-width:0` on both column wrappers.
- `.prism-mt-term` → `flex-wrap:wrap`; label → `flex:0 1 auto;min-width:0` +
  `overflow-wrap:break-word`; slot → `flex:1 1 140px;min-width:0` so a long
  term drops the slot to its own line instead of squeezing/overflowing.
- `overflow-wrap:break-word` added to `.prism-mt-def`/`.prism-mt-slot`.
- `.prism-mt-check{float:right}` → `display:block;margin:12px 0 0 auto`
  (float was harmless here but auto-margin is the non-legacy way to right-align
  a block-level button).
- Added `Terms`/`Definitions` column headers (parity with the React renderer,
  and useful once the columns stack).
- Rewrote the inline interaction script: kept drag/drop, added tap-to-select a
  definition → tap a term to place it, tap a filled term to send its
  definition back to the bank. Placeholder copy `Drop here` → `Tap or drop`.

**`packages/renderer/src/MatchingBlockRenderer.tsx`** (React preview-demo
component, kept in parity though not what the actual preview page renders):
same grid/wrap/break-word layout fix via inline styles, plus a
`selectedDefId` state for tap-to-place mirroring the export JS.

## Verification

- `pnpm -C packages/renderer run typecheck` → clean
- `pnpm -C apps/web run typecheck` → clean
- Manually traced the new interaction script logic (place/clear/select) for
  the drag path (unchanged behavior) and the new tap path.
- Did **not** load the actual preview iframe in a browser to visually confirm
  the stacked layout — recommend the user re-open Learner Preview at phone
  width and drag/tap a definition to confirm before considering this closed.
