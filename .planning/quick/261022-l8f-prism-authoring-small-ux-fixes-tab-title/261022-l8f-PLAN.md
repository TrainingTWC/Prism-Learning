<objective>
Three small authoring UX fixes in the Prism web app:

1. **Tab titles** — `document.title` reflects the open module so multiple open courses are distinguishable (editor and Learner Preview).
2. **Preview start options** — the editor's Preview control offers "From the beginning" vs "From this lesson" (the lesson being edited).
3. **Return to the edited lesson** — coming back from preview reopens the lesson that was being edited instead of resetting to the first lesson.

Purpose: Authors iterate edit -> preview -> edit constantly; today every preview round-trip dumps them back on lesson 1 and every tab reads "Prism Authoring".

Approach (Claude's discretion, no CONTEXT.md for this quick task): the active lesson becomes URL state (`?lesson=<id>` on the editor route, `?lesson=&returnTo=` on the preview route) via TanStack Router `validateSearch`. This makes reload, browser Back, the Back link, and the iframe Exit button all land on the right lesson with one mechanism, and needs no Convex/schema changes.

Output: one new pure helper module + test, one tiny hook, router search validation, and wiring in ModuleEditorPage + PreviewPage.
</objective>
